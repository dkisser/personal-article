## Browser-Bridge 推广日记（一） · 墨问

**Browser-Bridge 推广日记（一）**

Browser-Bridge 的核心功能做完了，本想着像以前一样直接上传 github 就完事儿了。但是，想了想又觉得这个产品毕竟是花了精力的，心底还是希望有人能认可。

那好吧，先来个小目标，先找到 100 个用户，得到10个好评。（如果用 github 的指标来看的话 100 个star）

我自己以前也做了一些开源项目，但都胎死腹中~~

现在想来，很大一部分是因为自己的心魔-害怕失败。这里的失败，不仅仅指产品本身的失败，更多的是对不确定性的害怕。

“害怕产品让人体验不好”、“害怕别人瞧不起里面使用的技术”、“害怕苦心经营却无人文津”、“害怕别人的冷嘲热讽”。

写到这里，我有了个新的角度来看待下面两个问题。

**一个产品的成败与其使用的技术是否强相关？**

大模型这东西确实需要很高的技术门槛，它是算法、数据、算力的集成产物。但 Agent 出来之前，这些大模型估值也并没有这么夸张，很多人说是泡沫，它并没有取得想象中的成功（大量用户、营收、话题度等等）。因为它只提升人单点 chat/思考 的效率，因为它不感知实际环境，为了让模型能连贯处理的信息，人还需要做很多工具来补充上下文。

当各式各样的 Agent 出来之后，我们发现模型拥有了更多实际生产数据，他能更好的用工具，能产生更好的结果。而这些 Agent 的设计似乎没有想象中的复杂，他不需要依赖很多的中间件，也不需要处理很多复杂的网络通讯等等，使用的仍然是很久之前的技术来补充上下文信息。

写到这里，我找到了第一个心魔，或者说是一种偏见。总觉得前沿的大模型、云产品这些总是依赖关键技术，技术决定成败。

**一个产品生命周期取决于那些关键要素(什么时候是个头儿)？**

如果是一个作为一个企业的员工，活儿干完了确实就结束了。但如果是作为一个持续运营的产品或者生态，它应该是在不断地迭代与反馈，产品在这个周而复始的过程中逐渐变得更加强大。所以，产品的生命周期完全取决有没有人用，而不是设计者的主观意愿！！

呼~~~

看来，毅力与心力便是我的另一个心魔。长期专注一件事，全力以赴，达成目标，我似乎有些畏手畏脚~

突然想起之前在连岳的公众号中看到的一个词“干中学”，如果不知道该不该干，会不会干，那就先干起来~
