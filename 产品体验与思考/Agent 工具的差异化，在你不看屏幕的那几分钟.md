## Agent 工具的差异化，在你不看屏幕的那几分钟

最近三天，我把之前构建的一个任务管理 App 重构了一遍——切领域模型，顺手把框架层从 Electron 换成 Tauri + Node。重构本身先不聊，这次换工具，我最大的收获其实是个很小的东西：我不用再盯着屏幕发呆了。

## 一、以前我得盯着它

以前跑 agent，我有个很蠢的习惯：人明明可以去干别的，但我走不了。

因为 agent 会在某个环节停下来等你确认，而它停下来的那一刻，你并不知道。我只能坐在那儿看它刷，刷到它停。

mac 自带的终端就是这个问题：它停下来等你，但不会提醒你。

## 二、现在手机上会震一下

换成 Ghostty 和 orca 之后，最直接的变化是：手机上有推送，桌面上有提醒。它要人介入的时候，我会知道；它做完了，我也会知道。

发呆时间就这么省出来了。就这么一个细节，但它是这次换工具里我最在意的一条。

## 三、图形化省下的不是操作，是决策

以前我建 worktree 用的是 `claude -w xxx` 。这其实就是原生 gh 的封装，claude 只是把位置固定在了当前项目的 `.claude/worktrees` 里。用完还得调个 skill 去退出 worktree，把收尾动作走完。能用，但每一步都得我自己记住。

orca 把这些变成了图形化，而且可以在创建 worktree、删除 worktree 之后挂自定义脚本。收尾那一步，不用我记着了。

所以我的感受是：还得是图形化界面。纯 CLI 太自由了，自由到大脑一下子就宕机。你得先决定怎么做，再决定做什么，再决定要不要做——这些决策，每一条都是注意力成本。

做产品也是。给自由是要有上限的，不是每个人都是爱迪生，能凭空发明改变世界的东西。设计出来的产品，不该是让用户在空白画布上自由创作。

## 四、接力的时候，我发现不同 harness 的体感不一样

我平时用的是 Kimi-k3 + MiniMax-M3.1-Flash-Preview 这个组合，两个 agent 接力跑。

Claude Code 遇到实现细节上的不确定，会弹个框问你要答案，agent 就此阻塞住，你回了它才继续。Codex 不会：能处理的它先处理掉，剩下不确定的写进执行结果里问你，你补什么它就再做什么。

差别的落点是同一个：谁来打断我，什么时候打断我。一个在你做事的时候插进来问，一个攒到最后一次性汇报。后者明显更省注意力。

## 五、模型通用，细节不通用

模型已经足够通用了，谁都能接到差不多的能力。模型这一层的差距，换一版模型就可能被抹平；体验这一层的差距抹不平，只能一点点攒。所以这类 agent 工具真正值得打磨的，是那些能省下用户注意力的小细节。

另外一句题外话：语言、框架这些选择没那么重要，重要的是你搞清楚这个框架要解决的问题，和你要解决的问题到底匹不匹配。

**为什么需要多个 agent 接力，我还没想明白。**

这两周我一直用两个 agent 接力，但说实话，我没搞清楚接力本身带来了什么。

是分工吗——一个负责想，一个负责做？是因为不同模型擅长的事本来就不一样？还是只是把等待从一个 agent 摊到了另一个 agent 上（它们都跑在本地，只是不同的进程、不同的 runtime），看起来热闹了一些？

我现在只能确定一点：接力过程中被暴露出来的差异，大部分不在模型身上，而在 harness 怎么处理“不确定”这件事上。至于要不要接力、值不值得接力，我还没想明白。
