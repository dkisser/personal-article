Design Philosophy

两种脚手架哲学:"掌控每一字节" vs "默认即正确"

Pi 设计哲学

"掌控每一字节"

从流式事件到 token 计数，每一层都暴露给你，因为 Agent 的行为值得被精确控制。 自研核心，精细控制，事件驱动，状态显式化。
DeepAgents 设计哲学

"默认即正确"

你不需要成为一个 Agent 专家才能使用 Agent — 我们把最合理的默认都打包好了。 站在巨人肩膀上，开箱即用，生态嫁接，batteries included。
设计倾向光谱
自建组件嫁接生态
显式配置约定优于配置
精细事件粗粒度拦截
零依赖生态最大化
启动速度优先功能完整优先
类型安全优先开发效率优先

互相借鉴的方向

Pi 可向 DeepAgents 学习

Middleware 架构 引入声明式 Middleware 堆栈概念，简化扩展开发的组合逻辑
BackendProtocol 抽象出可插拔存储后端，提高可测试性和可移植性
Profile 系统 按模型调优行为是高频需求，可通过扩展系统实现 HarnessProfile 机制
子代理原生支持 将 SubAgent 提升为一等公民，而非通过工具间接实现

DeepAgents 可向 Pi 学习

事件粒度 增加 text_delta/tool_execution_update 级别事件，提升可观测性
Lazy Provider 加载 按需加载 provider 模块，改善 CLI 启动速度
分支式会话 线性 checkpoint 可借鉴 Pi 的 fork/navigate 会话树设计
自研 TUI Textual 在极致性能场景下不如自研 TUI，重度 CLI 用户可能受益

两者都 在工具层引入权限控制
两者都 实现了上下文压缩/摘要
两者都 支持多 Provider 切换
两者都 走向 SubAgent 原生支持
两者都 采用 "信任 LLM + 边界控制" 安全模型
