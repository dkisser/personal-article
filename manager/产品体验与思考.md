- [[「云端Agent如何使用你本地机器的浏览器？」]] — 探讨云端Agent通过WebSocket连接使用本地浏览器的方案，核心挑战在于连接管理与安全认证。
- [[「CC-Switch还真是个不错的产品」]] — CC-Switch是一个能让Coding Agent无缝切换底层LLM供应商的工具，支持Claude Code、Codex等。
- [[「K2.7 Code 高速版，yyds」]] — 体验Kimi K2.7 Code高速版，申请快速通过，速度约普通版6倍，但5小时额度约2小时用完。包含在Coding Plan内，优于MiniMax强制套餐。
- [[「省Token利器-Claude-mem」]] — 介绍Claude-mem工具，通过mem-search MCP实现本地文件与向量检索，避免AI重复理解上下文从而节省Token，适合持续迭代的项目。
- [[「Claude-mem 核心原理解读」]] — Claude-mem 用 Observation+Summary 保留记忆，采用渐进式披露（title→summary→原内容）自动注入上下文，避免 RAG 召回开销。
- [[「Kimi Work 的半额 Token消耗突然不香了~」]] — Kimi Work 半额 Token 消耗看似划算，但迁移 Skills 和无法使用 Claude-mem 的隐形成本让迁移决心动摇。作者意识到工具切换不仅是功能比较，社区生态同样重要。
- [[「Run fast, Run first」]] — 从迷恋动态语言的快速构建，到发现 Java 之慢源于内心执念；Agent 时代应先找到用户愿意买单的方向。
- [[「从一条用户评论到Browser Bridge的新功能-Tab隔离」]] — 文章作者在掘金等平台发帖讨论Browser Bridge产品，收到用户评论后反思，找到了产品优化方向：Tab隔离。新版0.0.8实现了任务维度的tab隔离，提升多页面处理体验。作者仍在思考产品的核心用户群和竞品对比。
- [[「自从用上 Agents View 之后， 我的心力交瘁感消失了」]] — 用户分享使用Agents View替代Tmux管理Claude会话的体验。相比Tmux，Agents View界面美观，无需复杂配置，支持后台运行、多会话管理，解决了Tmux复制粘贴不便等问题。但Auto模式在非Claude模型上判断不准，需手动切换。整体提高了工作效率，减轻了心力交瘁。
- [[「RAG 入门到精通 - 最基础版本」]] — 作者因工作焦虑浏览招聘网，发现RAG技术成为Agent工程师的热门要求，于是从零搭建RAG系统。他以手冲咖啡选豆场景为例，从MVP开始：先确定店铺助手场景，再收集咖啡豆及店铺数据，最后用Chroma整合到LLM上下文。系统搭建后，作者指出生产环境需要更成熟的架构和评估优化系统。
- [[「RAG 入门到精通 - 构建评估系统」]] — 作者分享了从单一工程视角转变为系统构建视角的感悟。在完成RAG工程链路后，他意识到数据准备、持续优化和评估同样关键。因此，他提出了构建RAG评估系统的想法，包括在线数据埋点（记录chunk_id和完整上下文）以及离线评估（通过人工编写答案或模型生成Q&A进行对比），并介绍了召回率、精确率、MRR等评估指标及其对问题的定位作用。
- [[「Graphify拯救了我的钱包」]] — 作者分享了使用 Graphify 工具优化代码定位的体验。面对同事抱怨 Codex Pro 额度不够，作者推荐了 Graphify。利用 AST 索引，它能精准定位代码继承和调用链，减少大量文件读取。安装后需注意用 .graphifyingore 排除非代码文件。虽未明显节省 token，但定位效率显著提升。
- [[「RAG 入门到精通 - 一次完整的评估过程」]] — 本文介绍了 RAG 系统从构建到评估的完整流程。作者已搭建基础系统，但强调持续优化数据才是质变关键。通过 Agent 模拟买家和卖家生成高频问题与基准回答，构建初始数据集。随后运行评估并分析结果，确定优化方向（如补数据、加子标题）。文章展示了如何在没有标准答案时，利用模型生成基准水平作为参考。
- [[「RAG 入门到精通 - 生成的内容优化」]] — 探讨 RAG 系统生成侧的优化难题：严格遵循上下文导致常识问题失答，放宽则引发幻觉。作者尝试分类器和定制 Prompt，但混合场景仍待优化。
- [[「RAG 入门到精通 - Classifier & Sub-...」]] — 用分类器判断问题类型，对需要全量对比的问题走 Sub-query 拆分再合并召回结果；写死上下文数量为 20，但召回不全仍需精细调优。
- [[「RAG 从入门到精通 - 总结」]] — 作者总结RAG构建心得：真正重要的是评估与反馈循环，而非混合搜索、子查询等技巧。评测数据只能反映宏观问题，忠实度与有用性之间需要权衡，应充分发挥模型泛化能力。
- [[「构建了一款P2P的聊天工具」]] — 该页面描述了一位开发者因为需要频繁在Mac mini和MacBook之间传输代码、令牌和文本，但现有IM工具存在单点登录、实名认证等问题，于是自己构建了一个P2P聊天工具。该工具无需账号，通过命令行TUI界面实现点对点传输，支持文本和文件，并提供了GitHub链接。
- [[Spring 为何没有在 Java之外的地方存在？]] — Spring 起源于收拾 EJB 臃肿的烂摊子，终成 Java 企业开发事实标准。Java 静态类型特性迫其用反射与动态代理实现 IoC/AOP，而 Python 等动态语言用装饰器即可达到同样效果。
